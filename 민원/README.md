# 민원 이슈 모니터링

> ⚠ **실무(실제 데이터)로 쓰기 전에 [`실무전환_체크리스트.md`](실무전환_체크리스트.md)를 확인할 것.** 실제 데이터를 올리면 화면에도 남은 항목이 뜬다.

민원 엑셀을 올리면 이번 달 접수 현황과 이슈(테마 급증·단지 쏠림·키워드 이상치)를 바로 보여주는 정적 웹페이지.
서버·설치 없이 `index.html`을 브라우저로 열면 동작한다.

## 사용법
1. `index.html` 열기 (Vercel 배포 시 해당 주소, 또는 대시보드의 고객관리(민원) → 이슈 모니터링 탭)
2. 화면 위 **데이터 출처** 고르기
   - **대시보드 데이터** — 지우안 대시보드의 고객관리(민원) → 데이터 탭에 올린 엑셀을 그대로 사용(기본값). 그쪽에서 새로 올리면 이 화면도 즉시 갱신
   - **직접 올린 엑셀** — 이 화면에서 업로드 (또는 파일 끌어다 놓기)
   - **샘플 데이터** — 시연용 가상 데이터
3. 기준 월 선택 · 월 중간 / 월말 확정 전환
4. **AI 분석 실행** — Gemini API 키 필요 (각자 브라우저에만 저장)

- 직접 올린 엑셀은 파일에 들어 있는 **월 단위로 교체**된다. 같은 달을 다시 올려도 중복되지 않고, 다른 달은 유지된다.
- 데이터는 **각자 브라우저(localStorage)에만** 저장된다. 저장소에는 올라가지 않는다.
- **대시보드 연결**: 같은 주소(도메인)에 있을 때만 동작한다. 대시보드가 쓰는 저장 이름 `r9_vocRawRows`를 읽어 열 순서(접수일·고객명·접수내용·처리내용·구분·유형·접수경로·키워드·대표지역·상세지역·접수주체·계약종별·에너지바우처구분)대로 변환한다. 대시보드가 이 이름이나 열 순서를 바꾸면 `js/link.js`도 같이 고쳐야 한다.

## 엑셀 양식
`template/민원데이터_양식.xlsx` 참고. 제목행의 **열 이름으로** 찾으므로 열 순서는 자유.

| 열 | 필수 | 용도 |
|---|---|---|
| 접수일 | ● | 월·일자 집계 |
| 키워드 | ● | 테마 판정 (`js/config.js`의 `THEMES` 표기와 같아야 함) |
| 고객명 | 권장 | 단지별 집계, 서로 다른 고객 수 |
| 접수경로 · 접수주체 | 권장 | 챗봇·관리소 건을 고객 수에서 제외 |
| 처리내용 | 권장 | 비어 있으면 미처리로 집계 |

제목행이 없으면 기존 정제 양식 14열 순서(해당월~에너지바우처구분)로 읽는다.
열 이름 별칭은 `js/import.js`의 `XL_HEADERS`에서 추가.

## 파일 구성
```
index.html          화면 틀
css/style.css       스타일
js/config.js        ★ 판정 기준 — 테마·키워드 묶음, 하한값, 일반 단지 토큰 (조정은 여기서만)
js/site-tokens.local.js          사내 전용 실제 단지·브랜드명 (깃허브 제외 · 사내에서 파일로 공유)
js/site-tokens.local.example.js  위 파일 형식 예시
js/core.js          저장·날짜 파싱 등 공용
js/detect.js        이슈 판정 로직
js/render.js        화면 그리기
js/sample.js        샘플 데이터 생성 (가상 고객번호 · 가상 단지명, 2025.1~2026.9.18)
js/sample-ai.js     샘플 9월(월 중간)·8월(월말) AI 분석 예시 (실제 호출 결과 아님 — 화면에 표시됨)
js/ai.js            AI 분석 (Gemini 호출 · 결과 검증 · 화면)
js/link.js          데이터 출처(대시보드 연결 · 직접 업로드 · 샘플) 전환
js/import.js        엑셀 업로드
js/app.js           버튼·이벤트 연결
lib/xlsx.full.min.js  SheetJS 0.18.5 (Apache-2.0, 오프라인 동작용 동봉)
template/           업로드 양식
```
스크립트는 ES 모듈이 아닌 일반 `<script>`로 순서대로 읽는다 (로컬 파일로 열 때 모듈은 브라우저가 막음). `index.html`의 로드 순서를 바꾸지 말 것.

## 판정 기준 요약 (`js/config.js`)
- **테마**: 키워드를 5개 사안(요금 이의 / 난방 품질 / 설비 장애 / 요금 감면·납부 / 계약·전환)으로 묶어 판정. 하나의 사안이 여러 키워드로 흩어져 감지 못 하는 문제를 막기 위함
- **등급** (`THEME_RULES`, 위에서부터 우선)
  - 급증: 테마 8건 이상 + 전월 대비 +5건 또는 +60%
  - 비중 확대: 테마 8건 이상 + 전체 대비 비중 +5%p 이상
  - 감소: 전월 대비 -40% 이상 (전월 8건 이상일 때)
  - 월 중간에는 하한 8건을 경과 일수 비율로 낮춤(최소 4건), 전월도 같은 일수까지 잘라 비교
  - **전월 데이터가 없으면 판정하지 않음** (첫 업로드 때 전부 급증으로 뜨는 것 방지)
- **근거 줄** (등급 조건 아님, 해당되면 표시): 키워드 분산 · 서로 다른 고객 5명 이상 · 10일 창에 55% 집중 · 작년 동월 대비 +40% · 보조 신호 동반 · 단지 쏠림(40%) · N개월 연속
- **N개월 연속**: 직전 달들을 데이터로 다시 판정해 급증·비중 확대가 이어진 달 수를 셈 (최대 12개월)
- **보조 신호**: 열량계·설비점검 — 옆팀이 한 달치를 몰아 올리므로 독립 판정하지 않고, 당월 0건이면 '미유입'으로 표시
- **감지 제외**: 명의변경·자동이체 등 상시 행정 문의 10개
- 기준값은 초기값이므로 실데이터로 돌려보고 조정

## AI 분석 (`js/ai.js`)
- **역할 분리**: 건수 계산과 이슈 판정은 JS가 끝낸다. AI는 ① 접수내용을 읽고 원인·패턴·리스크 정리(AI 분석 칸) ② JS가 올린 이슈 후보가 실제로 하나의 사안인지 검증(이슈 카드에 한 줄로 표시)만 담당
- **AI는 이슈를 만들 수 없음**: 후보에 없는 테마를 내놓으면 화면에서 버림. 근거 없는 항목, 선정 이유 없는 사례도 버림
- **보내는 것**: 화면 통계 + 접수내용 표본 최대 120건(이슈 후보·다발 단지·미처리 우선). 고객명은 보내지 않고 단지명/개인/챗봇 구분만. 전화번호·동호수는 가림
- **키**: 각자 브라우저(localStorage)에만 저장, 호출은 브라우저 → 구글 직접
- 검증 결과는 이슈 카드에 "AI · 단일 사안 / 무관한 문의 겹침" + 조치 한 줄로 붙음 (무관이면 흐리게, 삭제는 안 함)
- 모델: `gemini-flash-latest` 기본, 없거나 과부하면 다른 모델로 자동 전환. 429·503은 자동 재시도

## 샘플 데이터
- 심사·시연용. 실제 고객·단지 정보 없음 — 고객명은 `고객 0000` 가상 번호, 단지명은 지역명만 실제
- 기간: 2025년 1월 ~ 2026년 9월 18일. **9월은 진행 중인 달**로 두고, 샘플을 볼 때는 오늘을 9월 19일로 고정 → 언제 열어도 처음 화면이 '월 중간'(8월 1~18일과 비교)
- 연출된 사안: 7월 단가 조정 → 요금 이의 3개월 연속(9월 고지서 후 재증가) / 청라크레이티브 아파트 공동난방비 배분 문의(8월) / 가정 홍당무 오피스텔 누수 집중(8월)·재발(9월) / 9월 계약·전환 '가짜 급증'(AI가 무관 판정하는 시연용) / 8·9월 열량계·설비점검 미유입
- 9월·8월 AI 분석은 미리 작성한 예시(`sample-ai.js`). 키를 넣고 다시 분석하면 실제 결과로 교체
- 엑셀을 올리면 샘플은 지워짐

## 주의
- 실제 민원 엑셀은 커밋하지 않는다 (`.gitignore`로 차단)
- 저장소는 **private** 유지 권장 — 판정 기준·키워드 체계가 사내 업무 로직
- 실제 단지·브랜드명은 `js/site-tokens.local.js`에만 둔다 (`.gitignore` 등록). 없으면 일반 단어(아파트·오피스텔 등)만으로 추정
- 고객명 분류는 **단지 지정만** 내보내기/가져오기로 공유 가능 (개인 지정은 실명이라 제외)
