# 실무 전환 체크리스트

대회용(샘플 데이터 · 공개 주소)에서 실무용(실제 민원 데이터)으로 넘어갈 때 확인할 항목.
실제 데이터를 올리면 화면 하단 **'실무 전환 점검'**에 1·3·4번이 자동으로 뜨고, 처리하면 사라진다.

| # | 항목 | 할 일 | 끝났는지 확인 |
|---|---|---|---|
| 1 | **단지명 목록 파일** | 사내에서 `site-tokens.local.js`를 받아 `js/` 폴더에 넣기 (깃허브에는 없음) | 화면 알림이 사라지면 끝 |
| 2 | 목록 공유 방식 개선 | 파일을 사람마다 주고받는 대신 한 곳에서 불러오게 바꾸기 — ① 단지 분류 내보내기/가져오기(지금도 가능) ② 구글 드라이브·사내 서버 ③ Vercel 보호 경로 | 팀원 수가 늘거나 목록이 자주 바뀌면 진행 |
| 3 | **판정 기준값 조정** | 실제 데이터로 한 달 돌려본 뒤 `js/config.js`의 `THEME_RULES` 조정, 끝나면 `RULES_REVIEWED=true` | 화면 알림이 사라지면 끝 |
| 4 | **Vercel 접근 제한** | Settings → Deployment Protection → Vercel Authentication을 **All Deployments**로 (대회 중에는 공개 상태) | vercel.app 주소에서 실제 데이터를 올리면 알림 |
| 5 | AI 키 운영 | 개인 키로 쓸지 팀 공용 키로 쓸지 결정 · 사내망에서 `googleapis.com` 접속되는지 확인 | AI 분석 1회 성공 |
| 6 | 데이터 공유 구조 | 지금은 각자 엑셀을 올려야 보임. 한 명이 올리면 모두 보게 하려면 공용 저장소 필요 | 필요 여부 결정 |
| 7 | 샘플 기능 정리 | 실무 배포에서 "샘플 데이터로 보기" 버튼과 `sample-ai.js`를 남길지 결정 | 결정 |

## 1번 파일 형식
`js/site-tokens.local.example.js` 참고. 받은 파일이 없으면 이 형식대로 새로 만들어도 된다.
